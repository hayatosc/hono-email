## EmailMessage

A fully rendered email message passed to an adapter.

```ts
type EmailMessage = {
  from: EmailAddress
  to: EmailAddress | EmailAddress[]
  cc?: EmailAddress | EmailAddress[]
  bcc?: EmailAddress | EmailAddress[]
  replyTo?: EmailAddress | EmailAddress[]
  subject: string
  html: string
  text: string
  attachments?: EmailAttachment[]
  headers?: Record<string, string>
  messageId?: string
  idempotencyKey?: string
  date?: Date
  envelope?: EmailEnvelope
  dkim?: EmailDkimOptions
}
```

#### `from` <Badge text="Required" variant="caution" size="small" />

Visible sender address. See [EmailAddress](#emailaddress).

#### `to` <Badge text="Required" variant="caution" size="small" />

Visible recipient address or addresses.

#### `subject` <Badge text="Required" variant="caution" size="small" />

Message subject line.

#### `html` <Badge text="Required" variant="caution" size="small" />

Rendered HTML body. Set automatically by `sendEmail()`.

#### `text` <Badge text="Required" variant="caution" size="small" />

Plain-text body. Set automatically by `sendEmail()`.

#### `cc` <Badge text="Optional" variant="note" size="small" />

Carbon-copy addresses.

#### `bcc` <Badge text="Optional" variant="note" size="small" />

Blind carbon-copy addresses.

#### `replyTo` <Badge text="Optional" variant="note" size="small" />

Reply-to address or addresses.

#### `attachments` <Badge text="Optional" variant="note" size="small" />

Message attachments. See [EmailAttachment](#emailattachment).

#### `headers` <Badge text="Optional" variant="note" size="small" />

Custom email headers as a `Record<string, string>`.

#### `messageId` <Badge text="Optional" variant="note" size="small" />

Custom Message-ID header value.

#### `idempotencyKey` <Badge text="Optional" variant="note" size="small" />

Idempotency key used to prevent duplicate deliveries on retries.

- For SMTP / raw MIME sends, derives a deterministic RFC 5322 `Message-ID` when `messageId` is omitted.
- For HTTP provider adapters (such as Resend), deduplication is handled via provider-specific mechanisms (e.g. the `Idempotency-Key` HTTP header) rather than `Message-ID`.

#### `date` <Badge text="Optional" variant="note" size="small" />

Message date.

#### `envelope` <Badge text="Optional" variant="note" size="small" />

SMTP envelope override. See [EmailEnvelope](#emailenvelope).

#### `dkim` <Badge text="Optional" variant="note" size="small" />

DKIM signing options. See [EmailDkimOptions](#emaildkimoptions).

## EmailMessageDraft

Email message with JSX instead of rendered `html`/`text`. Pass to `sendEmail()`.

```ts
type EmailMessageDraft = Omit<EmailMessage, 'html' | 'text'> & {
  jsx: Child
  render?: RenderOptions
}
```

#### `jsx` <Badge text="Required" variant="caution" size="small" />

Email JSX tree. Rendered to `html` and `text` by `sendEmail()`.

#### `render` <Badge text="Optional" variant="note" size="small" />

Render options applied before delivery. See [RenderOptions](/core/render/).

## EmailSendOptions

Common options accepted across delivery adapters and `sendEmail()`.

```ts
type EmailSendOptions = {
  signal?: AbortSignal
  retry?: RequestRetryOptions | boolean
}
```

#### `signal` <Badge text="Optional" variant="note" size="small" />

An `AbortSignal` used to cancel the send operation.

- **HTTP-based adapters** (Resend, SendGrid, Postmark, Mailgun, Cloudflare REST): Cancels in-flight HTTP requests and retry backoff sleeps immediately.
- **SES adapter**: Forwards the signal to the AWS SDK `SesClient.send()` method.
- **SMTP adapter (`SmtpTransport`)**: Cancels pre-send, queued connection waiters, connection opening, and in-flight session exchanges, closing the underlying socket and returning a non-permanent timeout failure receipt.
- **Cloudflare Workers binding**: Supports pre-send cancellation checks prior to invoking the binding.

#### `retry` <Badge text="Optional" variant="note" size="small" />

Per-send retry configuration. Set to `false` to disable retries (e.g. when called inside a job queue or transactional outbox worker), or pass `RequestRetryOptions` with custom intervals, jitter (`'full' | 'none'`), and attempts.

- **Supported adapters**: HTTP-based adapters (Resend, SendGrid, Postmark, Mailgun, and Cloudflare REST connector).
- **SES adapter**: Ignores per-send `retry`; configure retry behavior on the AWS SDK `SesClient` instance passed to `SesAdapter({ client })`.
- **Cloudflare Workers binding**: Ignores per-send `retry`.
- **SMTP adapter**: Does not retry failed sends.

## SendEmailOptions

Options for `sendEmail()`: all `EmailMessageDraft` fields, `EmailSendOptions`, plus an adapter.

```ts
type SendEmailOptions = EmailMessageDraft &
  EmailSendOptions & {
    adapter: EmailAdapter
  }
```

#### `adapter` <Badge text="Required" variant="caution" size="small" />

Delivery adapter (e.g. `ResendAdapter(...)`, `SmtpTransport`, `CloudflareEmailAdapter(...)`).

#### `signal` <Badge text="Optional" variant="note" size="small" />

AbortSignal to cancel sending and retry sleep. See [EmailSendOptions](#emailsendoptions).

#### `retry` <Badge text="Optional" variant="note" size="small" />

Override retry settings for this send (`false` to disable retries). See [EmailSendOptions](#emailsendoptions).

## SendEmailReceipt

Union of `SuccessfulSendReceipt | FailedSendReceipt`.

```ts
type SuccessfulSendReceipt = {
  successful: true
  messageId: string
  accepted: string[]
  rejected: string[]
  response: string
  queued?: boolean
  queuedRecipients?: string[]
}

type FailedSendReceipt = {
  successful: false
  accepted: string[]
  rejected: string[]
  errorMessages: string[]
  response?: string
  cause?: unknown
}
```

Narrow on `receipt.successful` to access success or failure fields:

```ts
const receipt = await sendEmail({ ... })
if (!receipt.successful) {
  console.error(receipt.errorMessages)
}
```

## EmailAddress

```ts
type EmailAddress = string | { address: string; name?: string }
```

Pass a plain email address (`'user@example.com'`), a display-name formatted string (`'Ada Lovelace <ada@example.com>'` or `'"Orders, Inc." <orders@example.com>'`), or an object with `address` and an optional display `name`.

> [!NOTE]
> Each `EmailAddress` must represent a single address. Comma-separated addresses in a single string (e.g. `'a@example.com, b@example.com'`) are rejected to prevent header and recipient injection vulnerabilities. To send to multiple recipients, pass an array: `to: ['a@example.com', 'b@example.com']`.

## EmailAttachment

```ts
type EmailAttachment = {
  filename?: string
  content?: string | Uint8Array | ArrayBuffer | ReadableStream<Uint8Array>
  path?: string
  href?: string
  contentType?: string
  contentDisposition?: 'attachment' | 'inline'
  cid?: string
  encoding?: 'base64' | 'hex' | 'utf8'
  headers?: Record<string, string>
}
```

#### `filename` <Badge text="Optional" variant="note" size="small" />

Attachment filename shown to recipients. Non-ASCII filenames (e.g. `'請求書-2026.pdf'`) are automatically encoded using both RFC 2047 encoded-word and RFC 2231 / RFC 5987 `filename*` parameters for broad email client compatibility.

#### `content` <Badge text="Optional" variant="note" size="small" />

In-memory attachment content. One of `content`, `path`, or `href` is required.

#### `path` <Badge text="Optional" variant="note" size="small" />

Remote URL or data URI to resolve as attachment content. Local files must be read by user code and passed as `content`.

#### `href` <Badge text="Optional" variant="note" size="small" />

Remote URL to fetch as attachment content.

#### `contentType` <Badge text="Optional" variant="note" size="small" />

MIME content type.

#### `contentDisposition` <Badge text="Optional" variant="note" size="small" />

`'attachment'` (default) or `'inline'`.

#### `cid` <Badge text="Optional" variant="note" size="small" />

Content ID for inline attachments referenced in HTML as `cid:...`.

#### `encoding` <Badge text="Optional" variant="note" size="small" />

Encoding for string content: `'base64'` | `'hex'` | `'utf8'`.

## EmailEnvelope

SMTP envelope override. Useful when the envelope sender differs from the visible `From` address (e.g. for bounce handling).

```ts
type EmailEnvelope = {
  from?: EmailAddress
  to?: EmailAddress | EmailAddress[]
  cc?: EmailAddress | EmailAddress[]
  bcc?: EmailAddress | EmailAddress[]
}
```

## EmailDkimOptions

DKIM signing options. Applied by the SMTP adapter and any adapter that supports DKIM.

```ts
type EmailDkimOptions = {
  domainName: string
  keySelector: string
  privateKey: string
  algorithm?: 'rsa-sha256' | 'ed25519-sha256'
  headerFieldNames?: string[]
  skipFields?: string[]
}
```

#### `domainName` <Badge text="Required" variant="caution" size="small" />

Signing domain (e.g. `'example.com'`).

#### `keySelector` <Badge text="Required" variant="caution" size="small" />

DKIM selector (e.g. `'mail'`).

#### `privateKey` <Badge text="Required" variant="caution" size="small" />

PEM private key string. Supports RSA PKCS#1/PKCS#8 and Ed25519 PKCS#8 private keys.

#### `algorithm` <Badge text="Optional" variant="note" size="small" />

**Type:** `'rsa-sha256' | 'ed25519-sha256'` · **Default:** auto-detected from key format (`'ed25519-sha256'` for Ed25519 keys, `'rsa-sha256'` for RSA keys)

DKIM signing algorithm (RFC 6376 / RFC 8463). Ed25519 signatures are generated using the Web Crypto API without external dependencies.

#### `headerFieldNames` <Badge text="Optional" variant="note" size="small" />

Header names to include in the signature.

#### `skipFields` <Badge text="Optional" variant="note" size="small" />

Header names to exclude from signing.

## EmailAdapter

The interface implemented by all delivery adapters.

```ts
type EmailAdapter = {
  send(message: EmailMessage): Promise<SendEmailReceipt>
}
```

Pass a custom implementation when no built-in adapter fits your provider.
